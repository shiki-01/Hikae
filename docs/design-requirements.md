# Hikae デザイン要件

Oct 7, 2026 · @shiki

## 1. デザインの前提

Hikae の画面は「いま安全かどうか」が一目で分かることを最優先にします。装飾よりも状態表示の明快さを重視し、Git の概念を連想させる図（枝分かれの線、ハッシュ値）は出しません。画面 ID は詳細設計書の3章と共通です。

| 項目 | 決定・前提 |
| --- | --- |
| トーン | 落ち着いた事務的な見た目。成功表示は控えめにし、警告と破壊的に見える操作だけを目立たせる |
| 対象 OS | Windows / macOS。タイトルバーは MVP では OS 標準を使う（macOS の信号ボタン左、Windows の操作ボタン右の差を吸収しなくて済む） |
| ウィンドウサイズ | 初期 1200×780、最小 960×600。最小幅で2ペインが崩れないこと |
| テーマ | ライト / ダーク（OS 設定に追従）。両方のデザインが必要 |
| フォント | OS 標準（macOS: Hiragino Sans、Windows: Yu Gothic UI / Meiryo UI）。等幅は差分表示のみ（SF Mono / Consolas 系） |
| 言語 | 日本語のみ。ただし英語化を見越し、ボタン幅は文字数 1.5 倍の伸びに耐えること |
| 実装 | SvelteKit（Svelte 5）+ Master CSS（rc 固定）。2章のトークン名をそのまま Master CSS の variables 名にする |
| アクセシビリティ | 本文コントラスト 4.5:1 以上、キーボードのみで全操作可能、フォーカスリング必須。状態を色だけで表さない（アイコン＋文言を併用） |

## 2. 基礎トークン

値はデザイン側で決め、ここでは必要なトークンの名前と用途だけを定義します。Claude Code には仮の値で実装させ、デザイン確定後に値だけ差し替える運用にします。

### 2.1 色

| トークン | 用途 | 備考 |
| --- | --- | --- |
| `bg` / `bg-subtle` / `bg-raised` | 画面背景 / ペイン背景 / カード・ダイアログ | 3段階 |
| `fg` / `fg-muted` / `fg-faint` | 本文 / 補足 / 無効・プレースホルダ |  |
| `border` / `border-strong` | 区切り線 / 入力欄・選択枠 |  |
| `accent` / `accent-fg` / `accent-subtle` | 主ボタン、選択状態 / 主ボタン上の文字 / 選択行の背景 | ブランド色 |
| `state-saved` | すべて保存済み | 緑系 |
| `state-unsaved` | 未保存の変更あり | 黄・橙系 |
| `state-sync` | アップロード待ち／取り込み待ち | 青系 |
| `state-danger` | ぶつかり、エラー、削除される側 | 赤系 |
| `diff-add-bg` / `diff-add-fg` | 差分の追加行 |  |
| `diff-del-bg` / `diff-del-fg` | 差分の削除行 |  |
| `diff-mod-bg` | 変更セル（xlsx）、変更箇所の強調 |  |
| `snapshot` | 自動保存の点（タイムライン） | 保存ポイントより弱い色 |
| `focus-ring` | フォーカス表示 |  |

### 2.2 タイポグラフィ

| トークン | 用途 |
| --- | --- |
| `text-title` | 画面タイトル（プロジェクト名） |
| `text-heading` | ダイアログ見出し、ペイン見出し |
| `text-body` | 本文、一覧の行 |
| `text-small` | 日時、件数、補足 |
| `text-mono` | 差分表示 |

### 2.3 余白・形状・動き

- 余白: 4 の倍数で `space-1`（4）〜 `space-8`（32）
- 角丸: `radius-sm`（入力欄・バッジ）、`radius-md`（カード・ボタン）、`radius-lg`（ダイアログ）
- 影: `shadow-overlay`（ダイアログ・メニュー）のみ。カードは枠線で区切り、影は使わない
- 動き: `duration-fast`（ホバー）、`duration-base`（パネル開閉）。OS の「視差効果を減らす」設定でアニメーションを止める

### 2.4 アイコン

既存のアイコンセット（Lucide 等、線の太さが揃ったもの）から選ぶ前提で、必要な意味だけ列挙します。

| 意味 | 使う場所 |
| --- | --- |
| 変更（鉛筆）、追加（＋）、削除（−）、名前変更（矢印） | 変更ファイル一覧の行頭 |
| 保存ポイント（塗り丸）、自動保存（小さな点）、いま（二重丸） | タイムライン |
| クラウド、アップロード（上矢印付き雲）、取り込み（下矢印付き雲）、オフライン（斜線付き雲） | ヘッダーの状態表示 |
| 見比べる、元に戻す（反時計回り矢印）、開く（外部リンク）、フォルダ | 行ごとの操作 |
| ぶつかり（稲妻または交差矢印）、警告、エラー、情報 | エラー・確認ダイアログ |
| ファイル種別（文書、表、画像、テキスト、PDF、不明） | 一覧、プレビュー |
| AI 提案（きらめき）、拡張機能（パズル）、設定（歯車） | 保存欄、設定 |

## 3. コンポーネント一覧

コンポーネントは全 30 種で、うち MVP に必要なものは 27 種です。「状態」列のすべてについてデザインが必要で、特にローディング・無効・エラーの抜けが実装時に問題になりやすい点に注意してください。

### 3.1 基本部品

| コンポーネント | バリアント | 状態 | フェーズ |
| --- | --- | --- | --- |
| Button | primary / secondary / ghost / danger、サイズ sm / md | 通常、ホバー、押下、フォーカス、無効、処理中（スピナー） | MVP |
| IconButton | ghost / subtle | 同上＋ツールチップ表示 | MVP |
| SplitButton | 「開く▾」用（主操作＋メニュー） | 同上、メニュー展開 | MVP |
| TextField | 1行 / 複数行（メモ欄） | 通常、フォーカス、エラー、無効、文字数表示 | MVP |
| Select / Dropdown | 標準 / 時点選択（日時＋メモの2行表示） | 通常、展開、無効 | MVP |
| Checkbox / Radio | 単体 / ラベル付き / 説明文付き | オン、オフ、無効、フォーカス | MVP |
| Toggle | 設定用 | オン、オフ、無効 | MVP |
| SegmentedControl | 2〜3択（並べる/重ねる、変更/履歴タブ） | 選択、非選択、フォーカス | MVP |
| Badge | 件数 / 状態（saved・unsaved・sync・danger） | — | MVP |
| Tooltip | 上下左右 | — | MVP |
| Menu | 項目、区切り、アイコン付き、無効項目 | ホバー、フォーカス | MVP |
| ProgressBar | 確定 / 不確定 | 進行中、完了、失敗 | MVP |
| Spinner | sm / md | — | MVP |
| Toast | info / success / warning / error、操作ボタン付き（「取り消す」） | 表示、自動消去中 | MVP |
| Dialog | 確認 / 警告 / エラー / フォーム | 表示、処理中（ボタン無効） | MVP |
| Tabs | 設定画面の縦タブ | 選択、非選択、フォーカス | MVP |

### 3.2 Hikae 固有の部品

| コンポーネント | 内容 | 状態・バリアント | フェーズ |
| --- | --- | --- | --- |
| StatusHeader | プロジェクト名、状態1行（2.2 の3状態）、取り込む・アップロードボタン、歯車 | すべて保存済み / 未保存あり / アップロード待ち / 取り込み待ち / 同期中 / オフライン / 要対応 | MVP |
| ProjectCard | 名前、フォルダパス、状態バッジ、最終保存日時、保存先（個人 / Org 名） | 通常、ホバー、フォルダ不明（E11）、同期中 | MVP |
| ChangeListItem | 種別アイコン、ファイル名、フォルダ（薄字）、変更種別 | 選択、非選択、ホバー、ぶつかり中 | MVP |
| DropZone | 変更一覧の下部と全体オーバーレイ | 待機、ドラッグ中（強調）、受付不可（大きすぎる） | MVP |
| SaveBar | メモ欄、AI 提案チップ、保存ボタン | 変更なし（無効）、入力可、AI 生成中、AI 提案あり、保存中 | MVP（AI は Phase 2） |
| TimelineItem | 点、日時、メモ、クラウド境界線 | 保存ポイント / 自動保存（折りたたみ・展開）/ いま / 選択中 / 「ここまでクラウド」線 | MVP |
| FileActionRow | ファイル名＋「見比べる」「元に戻す」「開く▾」 | 時点表示用 / 現在用 | MVP |
| DiffView | 左右2カラム、行番号、追加・削除行 | テキスト / docx 段落 / xlsx セル（「Sheet1!B3: 120 → 150」）/ 差分なし / 大きすぎて省略 | MVP（docx・xlsx は Phase 2） |
| ImageCompare | 並べる / 重ねる（スライダー）/ 差分強調 | 読込中、サイズ違いの画像 | Phase 2 |
| ConflictItem | ファイル名、2版の情報（日時・PC 名）、2択ラジオ、「別名で残す」チェック、見比べる | 未選択、選択済み、片方削除型（残す / 削除を受け入れる） | MVP |
| ImpactList | 影響ファイル一覧（いまの内容 → 戻した後） | 変更 / 取り除かれる / 復活する | MVP |
| OwnerPicker | 保存先（個人 / Org）のアバター付き選択 | 選択可、作成権限なし（灰色＋理由） | MVP |
| ModelCard | AI モデルの段階、容量、必要メモリ、DL ボタン | 未導入、DL 中（進捗）、導入済み、PC 条件を満たさない（灰色＋理由） | Phase 2 |
| IgnoreRuleRow | パターン、対象件数、削除 | 通常、追跡中ファイルあり（2択の導線） | Phase 2 |

## 4. 画面ごとのレイアウト

全画面は「上部ヘッダー＋本体」の共通枠に載せます。数値は最小幅 960px 時の目安で、デザインで調整して構いません。ダイアログは中央配置、幅は確認系 480px、フォーム系 560px、ぶつかり解消のみ全画面モーダルです。

### S0 初回ウィザード（3ステップ）

```text
┌────────────────────────────────────────┐
│              （ロゴ）Hikae                │
│     ① GitHub にログイン  ② 保存先  ③ 完了    │  ← ステップ表示
│ ┌────────────────────────────────────┐ │
│ │  ステップ本体（中央 480px 幅のカード）  │ │
│ └────────────────────────────────────┘ │
│                         [戻る] [次へ]  │
└────────────────────────────────────────┘
```

- ① ログイン: 説明1文、「GitHub でログイン」ボタン、Device Flow のコード表示（大きな等幅8文字＋コピー）、ブラウザ待機中の表示
- ② 最初のプロジェクト: D1 と同じ3択（既存フォルダ / GitHub から取得 / 新規作成）をカードで提示
- ③ 完了: 「このフォルダを見守っています」と状態の説明、プロジェクト画面へ

### S1 プロジェクト一覧

```text
┌ Hikae                         [＋ 追加]  ⚙ ┐
├──────────────────────────────────────────┤
│ ┌ProjectCard┐ ┌ProjectCard┐ ┌ProjectCard┐  │  ← グリッド（幅に応じ2〜4列）
│ └───────────┘ └───────────┘ └───────────┘  │
└──────────────────────────────────────────┘
```

- 並び順は最終表示日時。要対応（ぶつかり、フォルダ不明）のカードは先頭に寄せ、枠を `state-danger` にする
- 空状態: 中央にイラスト（任意）と「最初のプロジェクトを追加」ボタン

### S2 プロジェクト画面（変更タブ）

```text
┌ StatusHeader（高さ 56）───────────────────────────────┐
├ 左ペイン 280〜360（可変）─┬ 右ペイン（残り）─────────────┤
│ SegmentedControl[変更|履歴]│ FileActionRow（高さ 48）      │
│ ChangeListItem × n       │ プレビュー / DiffView          │
│ （スクロール）             │ （スクロール）                 │
│ DropZone（下部 72）       │                              │
├──────────────────────────┴──────────────────────────────┤
│ SaveBar（高さ 72〜120、メモ欄は2行まで自動拡張）           │
└───────────────────────────────────────────────────────┘
```

- 右ペインは選択ファイルの「いま」と「直前の保存」の差分を初期表示。差分が出せない形式はファイル情報（種類、サイズ、更新日時）と「開く▾」
- 変更なし時: 左ペインに「すべて保存済みです」と最終保存日時、SaveBar は無効状態
- 左右ペインの境界はドラッグで幅調整可能

### S3 プロジェクト画面（履歴タブ）

```text
├ 左ペイン ────────────────┬ 右ペイン ─────────────────────┤
│ [変更|履歴]               │ 時点の見出し（日時＋メモ）        │
│ TimelineItem × n         │ 変更されたファイル（FileActionRow）│
│ （無限スクロール）          │ ─────────────────────────── │
│                          │ [この時点の全ファイルを見る]       │
│                          │ [この時点の状態にまるごと戻す]     │
```

- SaveBar は履歴タブでは表示しない
- 「この時点の全ファイルを見る」は右ペインをツリー表示に切り替える（フォルダ階層＋各ファイルの「開く」「この版に戻す」）

### S4 比較ビュー

- 右ペインを全幅に広げるオーバーレイ（左ペインを隠す）。上部に時点選択 Select × 2 と入れ替えボタン、表示モード切替
- 本体は DiffView または ImageCompare。差分箇所への移動ボタン（前へ / 次へ）を右上に置く
- 閉じるボタンと Esc で元のタブへ戻る

### S5 設定（S6〜S8 を含む）

```text
┌ ← 戻る   設定 ──────────────────────────────┐
├ 縦タブ 200 ──┬ 本体（最大幅 640、左寄せ）──────┤
│ 一般          │ セクション見出し                 │
│ 取り込み       │ 項目行: ラベル＋説明 ／ 右に操作部品 │
│ アップロード    │ …                              │
│ 自動保存       │                                │
│ 保存しないファイル│  ← S6                          │
│ AI            │  ← S7                          │
│ 拡張機能       │  ← S8                          │
│ 詳細設定       │  ← advanced（折りたたみ）         │
```

- 設定は即時保存（保存ボタンなし）。影響の大きい変更のみ確認ダイアログ
- プロジェクト別に上書きできる項目は「このプロジェクトだけ変更」リンクを行内に置く
- S6: IgnoreRuleRow の一覧、「追加」から拡張子 / フォルダ / ファイル選択、追跡中ファイルがあれば2択の Dialog
- S7: 段階0〜4の ModelCard を縦に並べ、PC のメモリ・空き容量を上部に表示。詳細設定内に Ollama の接続先
- S8: 拡張機能の一覧（名前、対応形式、有効化 Toggle）。開発者モードは詳細設定内

### D1 プロジェクト追加（560px）

- 1段目: 3択カード（既存フォルダを見守る / GitHub から取得 / 新しく作る）
- 2段目（選択後に同じダイアログ内で切替）: フォルダ選択、名前、OwnerPicker、公開範囲（初期は非公開、公開を選ぶと警告文）
- GitHub から取得: 検索欄＋リポジトリ一覧（保存先ごとにグループ）＋保存先フォルダ

### D2 元に戻す確認（480px）

- 見出し（「10/4 18:02 の状態に戻します」）、ImpactList（最大 8 行で以降はスクロール）、安心文（「戻す前の状態は自動保存として残ります」）、ボタン（キャンセル / 元に戻す）
- 「元に戻す」は danger ではなく primary（取り消し可能な操作のため）

### D3 変更のぶつかり解消（全画面モーダル）

- 上部: 見出しと説明1文、件数
- 本体: ConflictItem の縦並び。行単位編集（Phase 2）は該当行から右側に3ペインのエディタを開く
- 下部固定: 「あとで」（secondary）、「解消して保存」（primary、全件選択まで無効）

### D4 エラー表示

- Dialog 版: アイコン、見出し（何が起きたか）、安心文（データは無事か）、主ボタン、閉じる、折りたたみの「技術情報を表示」（等幅、コピーボタン付き）
- Toast 版（E03・E04 など自動再試行するもの）: 画面右下、1行＋操作ボタン1つ

## 5. 状態表示・空状態・エラー表示のパターン

StatusHeader の状態1行は、次の優先順位で1つだけ表示します（上ほど優先）。各状態について、アイコン・色・文言・右側のボタンの組を1枚ずつデザインしてください。

| 優先 | 状態 | 文言例 | 色トークン | 右側のボタン |
| --- | --- | --- | --- | --- |
| 1 | 要対応（ぶつかり、中断された操作） | 対応が必要なファイルがあります | `state-danger` | 確認する |
| 2 | 処理中 | 取り込んでいます… / アップロードしています… | `state-sync` | （なし、進捗のみ） |
| 3 | オフライン | オフラインです。保存はこの PC で続けられます | `fg-muted` | 再試行 |
| 4 | 未保存の変更あり | 未保存の変更が 3 件あります | `state-unsaved` | （SaveBar へ誘導） |
| 5 | 取り込み待ち | 別の PC の変更が 2 件あります | `state-sync` | 取り込む |
| 6 | アップロード待ち | アップロード待ちが 1 件あります | `state-sync` | アップロード |
| 7 | すべて保存済み | すべて保存済み・10/7 21:14 にアップロード | `state-saved` | 取り込む（控えめ） |

### 空状態

| 場所 | 表示 |
| --- | --- |
| S1 プロジェクトなし | 「最初のプロジェクトを追加」ボタン＋1文の説明 |
| S2 変更なし | 「すべて保存済みです」＋最終保存日時 |
| S3 履歴が1件のみ | タイムライン下部に「保存するたびにここに並びます」 |
| S4 差分なし | 「この2つの時点で内容は同じです」 |
| プレビュー非対応 | ファイル情報＋「既定のアプリで開く」 |
| S7 モデル未導入 | 「AI を使わなくても、メモは自動で提案されます」 |

### ローディング

- 一覧系（S1、変更一覧、タイムライン）はスケルトン表示
- プレビュー・差分は 300ms 以上かかる場合のみスピナーを出す（ちらつき防止）
- 長い操作（取り込み、アップロード、モデル DL）は StatusHeader とトーストで進捗を出し、画面は操作可能なままにする

### エラー表示の使い分け

| 種類 | 表示方法 | 例 |
| --- | --- | --- |
| 自動で回復する | Toast（warning） | ネットワーク断、GitHub 障害 |
| ユーザーの選択が必要 | Dialog | 大きいファイル、ぶつかり、フォルダ不明 |
| 操作の結果の失敗 | Dialog（error） | ファイル使用中で戻せない、容量不足 |
| 補助機能の失敗 | 該当箇所の小さな注記のみ | AI 提案、拡張機能のプレビュー |

## 6. デザイン作業の優先順位

Claude Code は Phase 0（技術検証）から始めるため、画面が必要になるのは Phase 1 の途中からです。最初にトークンと StatusHeader を決めれば、仮デザインのまま実装を進められます。

- [ ] 色・タイポグラフィ・余白のトークン値（ライト / ダーク）
- [ ] StatusHeader の7状態
- [ ] S2 変更タブ（ChangeListItem、SaveBar、FileActionRow を含む）
- [ ] S3 履歴タブ（TimelineItem の全バリアント）
- [ ] DiffView（テキスト）と S4 比較ビュー
- [ ] D2 元に戻す確認、D3 ぶつかり解消
- [ ] S1 プロジェクト一覧、D1 プロジェクト追加、OwnerPicker
- [ ] S0 初回ウィザード
- [ ] D4 エラー表示（Dialog / Toast）と空状態
- [ ] S5 設定の枠組み
- [ ] アプリアイコン（Windows / macOS の各サイズ）
- [ ] Phase 2 以降: ImageCompare、ModelCard、IgnoreRuleRow、S6〜S8
