# Phase 2 ローカル LLM モデル評価（保存メモ生成）

評価日: 2026-10-10。対象: `docs/design.md` 10章の段階2（ファイル名・変更種別・テキスト差分・docx/xlsx 抽出差分を入力に、保存メモの提案を 1 文生成）。
このレポートは事実と観察のみを記載し、モデルの優劣の最終判断は含めない。

システムプロンプト（全モデル共通）:

```text
あなたは、ファイルの変更内容から「保存メモ」を書く assistant です。
規則:
- 出力は日本語で 1 文のみ。40 文字程度まで。
- 与えられた情報にある事実だけを書く。推測や評価は書かない。
- 専門用語（commit、diff、push、branch、repository など）は使わない。
- ファイル名や、変更前後の具体的な値が分かる場合は、それを使う。
- 前置き、説明、引用符、記号の装飾は付けない。メモの文だけを出力する。
```

ユーザーメッセージ: `次の変更の保存メモを書いてください。` + 入力（変更ファイルの表 + 差分の要約）。入力の全文は評価用スクリプトの `inputs.json`（12 件、リポジトリ外）に保存してある。入力のタイトルは下表の左列を参照。

### 選定理由と除外した候補

- 選定の根拠（出典）:
  - classmethod「local llm guide 2026 summer」（https://dev.classmethod.jp/en/articles/local-llm-guide-2026-summer/）: 8GB 帯の小型モデルとして Qwen3.5-4B、Gemma 4 E4B / E2B を挙げ、Qwen3.5 と Gemma 4 の日本語を ◎ と評価している（ファミリー単位の評価で、サイズ別ではない）。
  - Qwen3-4B-Instruct-2507: 1 世代前の Qwen の 4B で、Qwen3.5 との比較基準として採用。日本語の個別ベンチマークは確認できなかった。
  - LFM2.5-1.2B-JP: 日本語向けに調整された 1.2B モデル（Hugging Face のカードに ja 対応と記載）。小型側の下限を見る目的で採用。ベンチマーク値（benchlm.ai のページ）は「準備中」で、比較可能な数値は得られていない。
  - 日本語の小型モデル同士を直接比較した公開ベンチマークは、今回の調査では見つからなかった。
- Gemma 4 E4B（`unsloth/gemma-4-E4B-it-GGUF`）は、Q4_K_M が 4,977,171,584 byte で 1 モデル 4.5GB の上限を超えるため見送り、同ファミリーの E2B を代わりに評価した（E4B の ggml-org 版 Q4_0 は 4,590,807,392 byte で、これも上限超過）。E4B の結果は本レポートに含まれない。
- Llama 3.2 3B: ライセンスが Llama 3.2 Community License（独自、再配布時の表示義務と利用規約の制約あり）で、日本語は公式対応言語に含まれないため候補から外した（評価していない）。
- Phi-4-mini: ライセンスは MIT だが、日本語の公式な強調がないため候補から外した（評価していない）。
- Sarashina / llm-jp / ELYZA: 今回の調査では、1〜4B 級で最新世代の GGUF 配布を確認できなかった（llm-jp-4 は 32B-A3B のみ確認）。評価していない。
